# 공통 엔진 요약

스터디 세 조가 함께 쓰는 에이전트 엔진의 핵심만 정리한 문서입니다. 이 레포의 산출물(`research-center/`)은 이 엔진의 출력 위에 만들어집니다. 코드와 조원용 가이드의 원본은 배포 레포 [KFA-ai-agent-study](https://github.com/phm0305/KFA-ai-agent-study)에 있습니다.

## 엔진의 네 칸

| 칸 | 하는 일 | 원본 위치 | 상태 |
|---|---|---|---|
| 1. 수집 | 어떤 소스든 같은 공통 표로 받아오기 | `tools/collect.py` | 완료 (2회차) |
| 2. 공통 표·출처 목록 | 줄마다 고유 번호(rid), 출처마다 [S#] | `tools/engine.py` | 계획 |
| 3. 지표 계산 | 지표(M#)를 계산식·입력 줄과 함께 저장 | `tools/engine.py` | 계획 |
| 4. 주장·숫자 대조 | 글에 적은 숫자를 지표와 비교해 PASS / REVIEW / FIX | `tools/engine.py` | 계획 |

## 수집: 입구 다섯 개, 출구 하나

소스는 자동화 정도에 따라 1 공식 API, 2 파이썬 라이브러리, 3 파일 다운로드, 4 크롤링, 5 수동 입력으로 나눕니다. 단계마다 다른 것은 표를 받아오는 부분뿐이고, 꼬리표·숫자·날짜 정리와 상태 판정은 한 함수(`finalize`)에서 합니다. 그래서 새 소스를 붙일 때는 읽는 부분만 새로 쓰면 됩니다.

공통 표는 숫자 하나가 한 줄이고 칸은 15개로 고정입니다: 종목코드, 종목명, 항목, 값, 단위, 기준(연결/별도), 기준일, 공시일, 출처, 출처 URL, 신뢰도(상/중/하), 수집 방법, 수집 시각, 상태, 비고.

상태는 두 값뿐입니다. 형식 통과는 모양이 맞다는 뜻일 뿐 숫자가 맞다는 뜻이 아니고, 코드가 혼자 판단할 수 없으면 확인 필요로 사람에게 넘기며 이유를 비고에 남깁니다. 확인 필요가 되는 경우는 필수 칸이 비었을 때, 값이 숫자로 안 바뀔 때, 날짜가 이상하거나 공시일이 기준일보다 빠를 때, 그리고 4·5단계(크롤링, 수동) 값 전부입니다. 빈칸은 "모른다"이고 `해당 없음`은 "그 개념이 없다"(예: 주가의 연결/별도)라서 둘을 구분합니다. 공시일은 미래 정보를 쓰지 않으려고 두는 칸이라, 모를 때 추측으로 채우지 않습니다.

검증: 테스트 59개가 pandas 3.0.5와 2.2.3에서 통과했고, 노트북을 정상·키 없음·인터넷 끊김·robots 차단 네 상황에서 끝까지 실행해 확인했습니다. 실제 사이트 응답은 일부만 Colab에서 확인했습니다.

## 엔진 불변식 (2~4칸)

1. 지표 값은 그 지표에 적힌 입력 줄만으로 다시 계산할 수 있다.
2. 입력이 없거나 확인 필요이면 지표 값을 비우고 이유를 적는다. 추정값으로 채우지 않는다.
3. 주장에 적힌 숫자는 지표(M#)나 원본 줄(rid)을 하나 이상 가리킨다. 가리키는 것이 없으면 REVIEW.
4. 같은 입력이면 출처 번호 [S#]가 매번 같다.
5. 같은 사실(종목·항목·기준·기준일·출처)이 두 줄이면 멈춘다.

이 불변식이 지켜지면 리포트의 모든 숫자를 원본 줄까지 거꾸로 따라갈 수 있고, 그것이 산출물 2(검증 기록지)의 ① 숫자 대조가 기대는 성질입니다.
